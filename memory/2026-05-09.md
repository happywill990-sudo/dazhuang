## SSE 解析错误关键发现

### 问题
- 三条通过 feishu 报告：`Could not parse Anthropic SSE event message_stop: Unexpected non-whitespace character after JSON at position 308`
- 来自三条调用 `mt/claude-opus-4-6`（端点 `api.9cubic.cn/v1`）时的运行时错误

### 关键事实
- **原始 SSE 数据从未完整写入磁盘文件** — 是 JS 运行时的内存异常
- session/trajectory/checkpoint 文件中只存了截断后的 error message
- 报错中的 `data=...` 截断是 JS Error 对象自身的限制（position 308 限制消息长度），不是文件内容被截
- 完整 SSE data 共 3 个 JSON 对象被 `api.9cubic.cn/v1` 塞进同一条 `data:` 行：
  1. `message_start`（含 usage/cache 字段）
  2. `content_block_start`（index 0, text: ""）
  3. `content_block_delta`（index 0, text: "[["）
- **根因：** `api.9cubic.cn/v1` 返回的 SSE 格式有问题，不应将多个事件合并到同一条 data 行

### 相关文件（含截断版本）
- `~/.openclaw-OCCoding/agents/main/sessions/03b49e2a-be71-4fca-9ffd-475095a08405/checkpoint.*.jsonl` — 三条转发的截断消息
- `~/.openclaw-OCCoding/agents/main/sessions/03b49e2a-be71-4fca-9ffd-475095a08405/trajectory.jsonl` — 大壮处理轨迹
- `journalctl --user -u openclaw-gateway-OCCoding.service` — systemd 日志含截断 stack

### 教训
- 不要再搜索"完整 SSE 原始数据文件" — 它不存在于磁盘
- 错误消息中 position 308 之后缺失的内容已知且可还原
