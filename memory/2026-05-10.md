# 2026-05-10

## 三条（默认实例 18789）问题排查

### 背景
- 三条（`~/.openclaw/` 默认配置，端口 18789）的 Feishu DM 报错：`Could not parse Anthropic SSE event message_stop`
- 错误模型：`claude-opus-4-6`，供应商 `mt`（api.9cubic.cn/v1）
- 根因：api.9cubic.cn 把多个 SSE 事件拼到同一个 data 字段里，没有换行分隔，JSON.parse 失败

### 检查结果
- 三条的 `~/.openclaw/openclaw.json` 中 **没有 mt provider**（之前以为有，实际没有）
- 但 `compshare provider` 在三条中只有 `claude-sonnet-4-6`，没有 `claude-opus-4-6`，所以 opus 模型实际走的是 mt（默认实例的）
- 三条有一个飞书 DM 会话 `ou_e5f4cf011de5e43786fe1d2956a0f190` 用的 `claude-opus-4-6`
- 三条的 `agents.defaults.model.primary = minimax/MiniMax-M2.5`

### 修改内容
1. **compshare provider** 添加 `claude-opus-4-7` 模型
2. **mt provider** 添加 `claude-opus-4-7` 模型
3. **agents.defaults.models.allowlist** 添加二者的别名配置
4. **agents.defaults.model.primary** 改为 `compshare/claude-opus-4-7`
5. **agents.defaults.model.fallback** 改为 `deepseek/deepseek-reasoner`
6. 移除了 `mt/claude-opus-4-6` 的 allowlist 条目
7. 重启三条生效

### 结论
- mt 的 SSE 问题无法从客户端修复，是服务端 api.9cubic.cn 的问题
- 三条现在默认走 compshare 的 claude-opus-4-7，mt 作为额外选项保留并可走 opus-4-7
